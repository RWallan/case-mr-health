# Relocar o MLflow versionado após o clone

Status: ready-for-agent
Type: task
Parent: #1
Blocked by: #32

## What to build

O `mlflow.db` versionado guarda caminhos absolutos do ambiente de quem o gerou. O clone em outro diretório precisa funcionar sem editar o banco à mão.

Um comando do CLI (por exemplo `case-mr-health ajustar-mlflow`), idempotente, reescreve os caminhos para o diretório atual: descobre o prefixo antigo sozinho (a partir de `experiments.artifact_location`) e troca nos 4 campos conhecidos (`runs.artifact_uri`, `logged_models.artifact_location`, `experiments.artifact_location`, `model_versions.storage_location`). Mostra quantos valores mudou e falha com mensagem clara se o banco não existir. Roda sobre `Settings.mlflow_tracking_uri`.

Alternativa a avaliar no começo da issue: gravar caminhos relativos ou usar `mlflow_artifact_dir` para evitar a reescrita. O MLflow exige URIs absolutas nesses campos, então a reescrita é a hipótese de trabalho, a confirmar.
