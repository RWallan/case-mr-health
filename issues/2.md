# Base consolidada e relatório de qualidade a partir das planilhas brutas

Status: ready-for-agent
Type: task
Parent: #1

## What to build

O analista roda um comando de CLI (`preparar-dados`) que lê as três planilhas brutas (pedidos, itens de pedido e cadastro de SKUs) com DuckDB, sem alterá-las, e obtém uma base consolidada persistida em DuckDB que relaciona pedido, item de pedido e SKU. Junto vem um relatório de qualidade que permite confiar na base.

Regras da base consolidada (spec #1):

- itens de pedido repetidos (mesmo SKU no mesmo pedido) têm as quantidades somadas e aparecem listados no relatório de qualidade;
- valor do item = quantidade × valor unitário;
- valor total do pedido = soma dos valores dos itens (a coluna original está 100% vazia);
- SKU sem cadastro, quantidade negativa e data inválida são rejeitados com mensagem clara.

O relatório de qualidade cobre integridade referencial, cardinalidade, duplicidades, nulos, tipos e perdas nos joins.

Este ticket também cria o esqueleto mínimo que os próximos reutilizam: o objeto de configuração (pydantic-settings) com os caminhos de dados, o logging com loguru e a CLI com cyclopts, substituindo o `print` atual do entrypoint.

O notebook de EDA nasce aqui com as seções independentes **por fonte** (pedidos, itens de pedido, SKUs) e **de relacionamento**, rodando de ponta a ponta a partir dos dados brutos. Os fatos levantados na Fase 0 são reconferidos aqui, não assumidos.

Os arquivos brutos e o PDF do case passam a ser versionados no diretório de dados brutos, sem alteração de conteúdo.
