# Entrada manual e por XLSX no dashboard

Status: resolved
Type: task
Parent: #1
Blocked by: #15, #22

## What to build

O usuário pede previsões pelo dashboard, preenchendo um formulário simples ou enviando um XLSX, e baixa o template. A validação prévia usa os atributos nativos do HTML, e os erros devolvidos pelo backend (campo e linha) aparecem numa tabela.

## Acceptance criteria

- [x] Formulário de entrada manual com validação prévia
- [x] Upload de XLSX e download do template
- [x] Exibição dos erros do backend com campo e linha
- [x] `npm run build` sem erros
- [x] Fragmento towncrier `24.adicionado.md`

## Answer

Novo componente `frontend/src/EntradaPrevisoes.svelte`, montado em `App.svelte` com uma importação e uma tag (`<EntradaPrevisoes />`), sem alterar o resto do arquivo. Contém: (1) formulário manual com `required`, `type="date"` com `pattern`, `min`/`max` do horizonte conforme a granularidade (1 a 14 diária, 1 a 2 semanal) e `step="1"`, enviado como lote de um item a `POST /predicoes/lote`; (2) upload de XLSX (`accept=".xlsx"`, `required`) a `POST /predicoes/lote/xlsx`, com link de download de `GET /predicoes/lote/template.xlsx`; (3) tabela de erros do backend (`detalhes[].campo` e `mensagem`; em planilha o campo traz `linha N / coluna`, no JSON `itens.<posição>.<campo>`); (4) tabela de resultados (linha, série, períodos, total previsto). Reaproveita as classes `card`, `update`, `primary`, `error`, `erros` e `update-status`.

Números: `npm run build` conclui sem erros nem avisos (Vite 7, 110 módulos). Sem testes de navegador, por decisão do projeto; nenhum Python alterado.

Limitações: a lista de SKUs é fixa no front, como em `App.svelte`; a validação nativa não conhece o limite de data do modelo (o backend devolve o erro na tabela); o componente não atualiza o gráfico principal, só mostra o total por solicitação. O build foi feito numa cópia temporária porque o `node_modules` do worktree está incompleto.
