# Sumário XLSX filtrado, comparação entre SKUs e links de changelog e Swagger

Status: resolved
Type: task
Parent: #1
Blocked by: #16, #17, #22

## What to build

- O gestor baixa um sumário em XLSX das análises que está vendo, respeitando os filtros de SKU e granularidade. O sumário diz explicitamente quando cobre o conjunto completo e não um filtro.
- O gestor compara a evolução da demanda entre os SKUs num único gráfico de linhas.
- O usuário acessa a documentação da API (Swagger) e o changelog estruturado por links no cabeçalho, ao lado do link do MLflow (#22). Sem abas.

## Acceptance criteria

- [x] Download do sumário XLSX respeitando os filtros, com a indicação de escopo
- [x] Gráfico de comparação entre SKUs
- [x] Links de Swagger e changelog no cabeçalho
- [x] `npm run build` sem erros
- [x] Fragmento towncrier `25.adicionado.md`

## Answer

A exportação `GET /previsoes/exportacao.xlsx` do #16 já filtrava por SKU e granularidade, mas não dizia o escopo. Ganhou a aba `Escopo` (Escopo = Completo/Filtrado, SKU, Granularidade, Linhas, Gerado em) e o cabeçalho `X-Escopo`. No dashboard, o componente `ComparacaoSkus.svelte` desenha as séries dos 4 SKUs num gráfico SVG de linhas (granularidade escolhida, via `GET /series/{sku}/{granularidade}`) e baixa o sumário respeitando duas caixas de filtro (SKU e granularidade), mostrando o escopo antes do download. `LinksApi.svelte` põe Swagger (`{api}/docs`) e Changelog (`{api}/changelog`, JSON do #20) ao lado do link do MLflow, sem abas.

Verificação: 2 testes novos em `tests/test_api_consultas.py` (13 no arquivo); `uv run poe test-rapido`: 565 passed, 48 deselected; `npm run build` sem erros. Limitações: o gráfico compara quantidades absolutas (sem normalização); o link de changelog abre o JSON, sem página própria; o sumário é o histórico de previsões já servidas (vazio se nenhuma foi feita); não testado no navegador.
