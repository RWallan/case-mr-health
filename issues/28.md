# Ingestão de pedidos novos e reconstrução das séries

Status: resolved
Type: task
Parent: #1
Blocked by: ADR 0011 (aprovado)

## What to build

Dado o par de XLSX de pedidos e de itens de pedido, valida com as regras de `preparar_dados` (erros com campo e linha), acrescenta à base apenas os pedidos novos e reconstrói `serie_diaria` e `serie_semanal`. Rejeita pedido já presente na base e arquivo já aplicado (SHA-256). Registra o hash dos dados resultante. Função de serviço, sem rota (a rota é o #30).

## Acceptance criteria

- [x] Ingestão incremental com validação por campo e linha
- [x] Rejeição de pedido repetido e de arquivo já aplicado
- [x] Séries reconstruídas e hash dos dados registrado
- [x] Testes (Seam 1) com planilhas sintéticas
- [x] Fragmento towncrier `28.adicionado.md`

## Answer

`src/case_mr_health/atualizacao.py` (`ingerir_pedidos`) valida o par de XLSX com as regras de `dados.py` (planilha e linha de cada problema), recusa pedido que já existe na base e par de arquivos já aplicado (SHA-256), acrescenta só os pedidos novos (itens repetidos do pedido somados) e reconstrói `serie_diaria` e `serie_semanal` em `db_path`, tudo numa transação. Cada atualização grava `hash_dados` encadeado (`base` → atualizações) na tabela `atualizacoes` e uma cópia dos arquivos em `atualizacoes_dir`. A visão de desenvolvimento e o OOT não são tocados.

**Números.** `tests/test_atualizacao.py`: 14 testes passam. Suíte rápida: 541 passaram, 48 lentos fora; evidência em `.ds-workflow/test-evidence/test-run-20261030T094959-1151433.json`.

**Limitações.** Aceita pedidos novos, não correções de pedidos antigos. A trava `ACESSO_BASE` serializa o acesso a `db_path` dentro de um processo; vários processos não são suportados (ADR 0005).
