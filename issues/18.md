# Especificação detalhada da regra de recomendação

Status: resolved
Type: grilling
Parent: #1
Blocked by: #6

## What to build

A especificação detalhada da regra de recomendação, apresentada e aprovada pelo usuário antes da implementação (ADR 0004). Parte do ADR 0004:

- usa o modelo semanal: compara a demanda média prevista para as próximas 2 semanas com a venda média das últimas 4 semanas;
- a distribuição histórica vem de janelas deslizantes com o mesmo formato (cerca de 7 variações);
- aumentos e reduções têm limites separados: Q3 das variações positivas e Q3 do módulo das negativas;
- os resultados possíveis são aumento significativo, redução significativa, estável e Insuficiente;
- toda recomendação leva aviso de baixa confiabilidade estatística.

A especificação precisa fechar, entre outros pontos:

- a fórmula exata da variação (relativa, e o tratamento de uma venda recente igual a zero);
- o número mínimo de variações positivas e negativas para o Q3 existir, abaixo do qual o resultado é Insuficiente;
- o método de cálculo do quartil com tão poucos pontos;
- se a confiança do modelo semanal (Insuficiente ou Ruim) afeta a recomendação;
- o vocabulário obrigatório: "pressão sobre o estoque", nunca ruptura.

Os casos de exemplo construídos aqui viram os testes do #19.

## Especificação (aprovada)

Decisões do usuário em 2026-10-30 (Q1 a Q12); aprovadas pelo usuário em 2026-10-30, junto com os 5 casos abaixo.

1. **Variação:** `(média prevista nas 2 próximas semanas − média vendida nas 4 últimas semanas) ÷ média vendida nas 4 últimas semanas`, em unidades semanais.
2. **Base zero:** média das 4 últimas semanas igual a 0 → `insuficiente`, motivo `sem_venda_recente`. Nas janelas históricas, a janela com base zero é descartada e não conta como positiva nem negativa.
3. **Histórico:** cada janela compara a média **real** das 2 semanas seguintes com a média real das 4 anteriores, deslizando uma semana por vez no período de desenvolvimento (sem o OOT selado). 12 semanas dão 7 janelas.
4. **Mínimo:** pelo menos 3 variações do lado da variação atual (positivas para aumento, negativas para redução); senão `insuficiente`, motivo `variacoes_insuficientes`. O outro lado não influencia. Variações iguais a 0 não contam para nenhum lado.
5. **Quartil:** Q3 por interpolação linear (`numpy.percentile`, método 7) sobre as variações positivas, ou sobre o módulo das negativas.
6. **Decisão:** significativa só se `|variação|` for **estritamente maior** que o Q3 do seu lado; caso contrário, `estavel`. Variação exatamente 0 é `estavel`, sem exigir mínimo.
7. **Confiança do modelo:** não afeta a recomendação (D-020, ADR 0008). Não há ADR novo.
8. **Origem e modelo:** modelo semanal da API (`champion` ou versão fixada), origem fixa `desenvolvimento_fim`. As 4 últimas semanas são as completas antes da origem; as 2 próximas são os passos 1 e 2 da previsão. Semanas sem venda entram como 0.
9. **Escopo:** só semanal, por SKU, série da rede. SKU sem modelo semanal → 404.
10. **Vocabulário:** "pressão sobre o estoque" (de alta ou de baixa), nunca "ruptura". Aviso fixo em toda resposta, inclusive `estavel`: "baixa confiabilidade estatística: poucas janelas históricas".
11. **Resposta** de `GET /recomendacoes/{sku}`: `resultado` (`aumento_significativo`, `reducao_significativa`, `estavel`, `insuficiente`), `motivo` (só em `insuficiente`), `variacao`, `limite_aplicado`, `media_vendida_4s`, `media_prevista_2s`, `n_variacoes_positivas`, `n_variacoes_negativas`, `texto`, `aviso`, versão e hash do modelo. A chamada é registrada no histórico DuckDB como as predições.

### Casos de exemplo (viram os testes do #19)

Série semanal em unidades, da semana mais antiga à mais recente (12 semanas, 7 janelas). As variações das janelas são `média(sem. i+5 e i+6) ÷ média(sem. i+1 a i+4) − 1`, arredondadas a 4 casas.

**Caso 1 — aumento significativo**
- Série: `10, 12, 8, 10, 14, 10, 12, 16, 14, 18, 16, 20`; previsão das 2 próximas: `24, 26`.
- Janelas: `0,2000; 0,0000; 0,3333; 0,3043; 0,2308; 0,3077; 0,2000` → 6 positivas (o 0 não conta).
- Base 17,0; prevista 25,0; variação `+0,4706`. Q3 das positivas `0,3069`. `0,4706 > 0,3069` → `aumento_significativo`.

**Caso 2 — redução significativa**
- Série: `20, 18, 22, 20, 16, 18, 14, 16, 12, 14, 10, 12`; previsão: `7, 9`.
- Janelas: `−0,1500; −0,1579; −0,2105; −0,1765; −0,1875; −0,2000; −0,2143` → 7 negativas.
- Base 12,0; prevista 8,0; variação `−0,3333`. Q3 do módulo `0,2053`. `0,3333 > 0,2053` → `reducao_significativa`.

**Caso 3 — estável**
- Mesma série do caso 1; previsão: `17, 19`.
- Base 17,0; prevista 18,0; variação `+0,0588`, abaixo do Q3 `0,3069` → `estavel` (com o aviso).

**Caso 4 — insuficiente por base zero**
- Série: `5, 0, 3, 0, 0, 0, 0, 0, 0, 0, 0, 0`; previsão: `2, 2`.
- Base das 4 últimas semanas = 0 → `insuficiente`, motivo `sem_venda_recente`. Nas janelas, 3 têm variação `−1,0000` e 4 têm base zero e são descartadas; nada disso é usado.

**Caso 5 — insuficiente por poucas variações**
- Série: `20, 18, 22, 20, 16, 18, 14, 16, 12, 14, 10, 10`; previsão: `16, 18`.
- Janelas: `−0,1500; −0,1579; −0,2105; −0,1765; −0,1875; −0,2000; −0,2857` → 0 positivas.
- Base 11,5; prevista 17,0; variação `+0,4783`, positiva, mas 0 < 3 positivas → `insuficiente`, motivo `variacoes_insuficientes`.

**Cobertura que os casos não esgotam:** limite exato (`|variação|` igual ao Q3 → `estavel`) e variação exatamente 0 serão testes unitários do #19 sobre a função pura, com valores construídos nela.
