# Recomendações, explicação e e-mail mockado no dashboard

Status: resolved
Type: task
Parent: #1
Blocked by: #20, #21, #22

## What to build

Na mesma página do dashboard, uma lista simples de recomendações. Aumentos e reduções significativos aparecem sinalizados de forma diferente, com a variação percentual, o Q3, o aviso de baixa confiabilidade e a explicação (indicando se veio do LLM ou do template). O gestor pode informar um e-mail e ver o conteúdo do alerta, e a tela deixa explícito que o envio é simulado.

## Acceptance criteria

- [x] Lista de recomendações com distinção visual entre aumento, redução, estável e Insuficiente
- [x] Visualização do e-mail mockado com o aviso de envio simulado
- [x] `npm run build` sem erros
- [x] Fragmento towncrier `23.adicionado.md`

## Answer

Componente `frontend/src/Recomendacoes.svelte`, montado em `App.svelte` (um import e uma tag). Lista os 4 SKUs via `GET /recomendacoes/{sku}`; cada cartão traz rotulo textual com sinal (▲ Aumento significativo, ▼ Redução significativa, ● Estável, ? Insuficiente) mais cor e borda (tracejada em Insuficiente), variação percentual, Q3, motivo quando insuficiente, aviso de baixa confiabilidade e a explicação com a origem (LLM ou template). O formulário (`type=email`, `required`, escolha de SKU) chama `POST /alertas/email` e mostra assunto, recomendação, semanas previstas com intervalos e o aviso `ENVIO SIMULADO` vindo do backend; erros do backend aparecem em alerta. `npm run build` passou sem erros nem avisos.

**Limitações.** Não verificado em navegador nem contra a API rodando. Cada carga da lista faz 4 chamadas de recomendação (com chave de LLM configurada, 4 chamadas pagas, sem cache). A recomendação é só semanal; independe do seletor de granularidade da página. O Q3 é exibido em % (a API devolve fração).
