# Envio de pedidos novos e gráfico atualizado no dashboard

Status: resolved
Type: task
Parent: #1
Blocked by: #22, #30

## What to build

Na página do dashboard, envio dos dois XLSX, acompanhamento do estado da atualização e atualização do gráfico (histórico e previsão) ao concluir. A tela avisa que a versão reajustada não tem métrica fora da amostra.

## Acceptance criteria

- [x] Envio e acompanhamento da atualização
- [x] Gráfico atualizado ao concluir
- [x] `npm run build` sem erros
- [x] Fragmento towncrier `31.adicionado.md`

## Answer

A página ganhou a seção "Enviar pedidos novos": dois campos de arquivo (.xlsx), envio para `POST /dados/pedidos`, tabela de erros com planilha e linha (422/409), acompanhamento por `GET /dados/atualizacoes/{id}` a cada 1,5 s com o resultado por série e, ao concluir, recarga do histórico e nova previsão. O resumo da previsão avisa quando a versão é reajustada (`origem_modelo = atualizacao`) e que ela não tem métrica fora da amostra; o rodapé deixa de dizer que nenhum treino é iniciado pela tela.

**Verificação.** `npm run build` sem erros (Vite, 109 módulos). Não houve verificação visual nem passada de fumaça com a API real: rodar o envio contra a base e o MLflow reais gravaria uma atualização de verdade, então fica para o #26 com dados de teste. Não há testes de navegador (decisão de escopo de 2026-10-30).

**Limitações.** Se a API reiniciar durante o reajuste, o acompanhamento recebe 404 e a tela mostra o erro; o estado das atualizações vive na memória do serviço.
