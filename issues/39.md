# API: `data_referencia` opcional, com padrão no fim do treino do modelo servido

Status: resolved
Type: task
Parent: #1

## What to build

Implementa o ADR 0013 no backend: `PedidoPredicao.data_referencia` passa a ser opcional (`src/case_mr_health/api/schemas/predicao.py`). Ausente, vale `modelo.desenvolvimento_fim` (último período do treino, normalizado na semanal), em `servicos/predicao.py::planejar`. Informada, o comportamento atual é preservado (validações de passo e limite).

- Valer também para o lote JSON e XLSX (`servicos/lote.py`, `schemas/lote.py`, template XLSX): coluna da data deixa de ser obrigatória; linha em branco usa o padrão.
- A resposta já devolve `data_referencia`; ela passa a ser a usada, para o frontend saber o início da previsão.
- Swagger (descrições, exemplos, 422) coerente com o código; exemplos sem a data.
- Sem mudança em modelos, pipeline de treino ou intervalos.

## Acceptance criteria

- [ ] `POST /predicoes` sem `data_referencia` responde 200 com a referência igual ao fim do treino do `champion`
- [ ] Com a data informada, as respostas e os erros 422 atuais não mudam (testes existentes continuam verdes)
- [ ] Lote JSON e XLSX aceitam a data ausente; o template e o Swagger refletem isso
- [ ] Testes nas duas granularidades, incluindo semana normalizada para segunda-feira
- [ ] `uv run poe lint` e `uv run poe test-rapido` verdes (no que tocar o backend)
- [ ] Fragmento towncrier `39.<tipo>.md`; registro em `docs/relatorio/registro-onda6.md`; seção `## Answer` nesta issue

## Answer

Entregue em 2026-10-30 (branch `39-referencia_opcional`).

- `PedidoPredicao.data_referencia` é `date | None` com padrão `None`. Em `servicos/predicao.py::planejar`, ausente vira `modelo.desenvolvimento_fim`, normalizado na semanal para a segunda-feira (a data devolvida é a usada). Informada, o caminho é o mesmo de antes: os 422 de passo negativo, de passo mais horizonte acima do limite e de data inválida não mudaram. Um `null` explícito no JSON continua rejeitado (`data inválida: None`), para não alterar o 422 existente; "ausente" é omitir o campo.
- Lote: o JSON herda o contrato; no XLSX, `data_referencia` saiu das colunas obrigatórias do cabeçalho (`OBRIGATORIAS = ('sku', 'granularidade')`) e célula em branco usa o padrão. O template traz as duas linhas de exemplo sem a data e as instruções dizem "data_referencia (opcional)".
- Swagger: descrições do campo e da resposta, docstring das rotas e exemplos sem a data (`PedidoPredicao` e `PedidoLote`); o exemplo da resposta mantém a data. Nenhum modelo, pipeline ou intervalo mudou.

Testes (novos): `test_sem_referencia_vale_o_fim_do_treino` (diária e semanal, igual ao pedido com a data do fim do treino), `test_sem_referencia_na_semanal_normaliza_para_a_segunda`, `test_lote_json_aceita_a_data_ausente`, `test_xlsx_com_data_em_branco_ou_sem_a_coluna_usa_o_fim_do_treino`; ajustados os testes que exigiam a data (`campo_ausente`, cabeçalho sem coluna obrigatória, template). `uv run poe lint` verde; `tests/test_api_predicao.py` e `tests/test_api_lote.py`: 101 passam; o resultado de `test-rapido` completo está no registro `docs/relatorio/onda6/39.md`.

Limitação: com os modelos atuais (`champion` nunca reajustado) a referência automática ainda cobre períodos já observados na base (fim do treino 2021-08-18 diária e 2021-08-15 semanal contra base até 2021-09-01). Isso se resolve com o reajuste do #40.
