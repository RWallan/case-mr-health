# #19 — Recomendação determinística na API

Data: 2026-10-30. Spec: `issues/18.md` (aprovada pelo usuário em 2026-10-30).

## Entregue

- `src/case_mr_health/recomendacao.py`: função pura `recomendar(vendas, previsao)` e `variacoes_historicas`.
- `src/case_mr_health/api/servicos/recomendacao.py`, `rotas/recomendacoes.py`, `schemas/recomendacao.py`; rota registrada em `api/app.py`.
- `servicos/predicao.py`: extraído `registrar_previsao` (resposta + histórico), reaproveitado pela recomendação; comportamento de `prever` inalterado.
- `tests/test_api_recomendacao.py` (31 testes); `changelogs/19.adicionado.md`.

## Decisões de implementação (dentro da spec)

- As 4 últimas semanas são as semanas de `serie_semanal` do banco de desenvolvimento com data até a segunda-feira da última semana do treino (`desenvolvimento_fim` − 6 dias). O OOT não é aberto.
- As 2 semanas previstas são os passos 1 e 2 do modelo; as duas linhas vão ao histórico (`data_referencia` = essa segunda-feira).
- Variação exatamente 0 é `estavel` com `limite_aplicado = null`; base zero devolve `variacao = null`.
- Texto fixo por resultado, com "pressão sobre o estoque"; teste garante a ausência de "ruptura".

## Desvio / ponto a confirmar

- Spec: "SKU sem modelo semanal → 404". Implementado 404 para SKU inexistente e 503 para SKU válido sem modelo servível (como no #14). Registrado em `issues/19.md`.
